    Running Simulations

    This page is the operational reference for installing the simulator, creating environments, running episodes, using the CLI and understanding the main execution parameters.

    Episode Loop Without a Controller

    For a first run with its expected output, and a comparison with the business-as-usual controller, follow the quickstart. The loop below is the smallest possible episode: it sends zero for every action, whose effect follows each device’s action contract.

    import numpy as np
from citylearn.citylearn import CityLearnEnv

schema = "citylearn_challenge_2022_phase_all_plus_evs"
env = CityLearnEnv(schema, interface="flat", episode_time_steps=24, render_mode="none")

observations, info = env.reset()
terminated = truncated = False

while not (terminated or truncated):
    actions = [np.zeros(space.shape, dtype="float32") for space in env.action_space]
    observations, reward, terminated, truncated, info = env.step(actions)

kpis_v2 = env.evaluate_v2()

env = CityLearnEnv(
    "citylearn_three_phase_dynamic_topology_demo",
    interface="entity",
    topology_mode="dynamic",

obs, info = env.reset()
specs = env.entity_specs

actions = {
    "tables": {
        "building": env.action_space["tables"]["building"].sample(),
        "charger": env.action_space["tables"]["charger"].sample(),
        "deferrable_appliance": env.action_space["tables"]["deferrable_appliance"].sample(),
    }

    Multi-Community Example

    Use MultiCommunityEnv when one training loop should step several independent communities in lockstep. Each child keeps its own physics, KPIs and demand-response files.

    from citylearn.multi_community import MultiCommunityEnv

env = MultiCommunityEnv(
    communities=[
        {
            "community_id": "community_a",
            "schema": "citylearn_challenge_2022_phase_all_plus_evs",
            "env_kwargs": {"interface": "entity", "episode_time_steps": 48},
            "weight": 1.0,
        },
        {
            "community_id": "community_b",
            "schema": "citylearn_challenge_2022_phase_all",
            "env_kwargs": {"interface": "entity", "episode_time_steps": 48},
            "weight": 1.0,
        },
    ]
)

observations, info = env.reset(seed=0)

    All communities must share seconds_per_time_step, effective episode length, interface, central_agent mode, physics_version, random_stream_version and baseline_version. evaluate_v2() returns local rows with community_id plus portfolio rows with level="portfolio". See multi_community_reference.md.

    Reward Observation Payloads

    step() builds a smaller reward observation payload when the reward function declares which observation names it needs. Built-in rewards already do this. Custom rewards can opt in with one of these compatible forms:

    class MyReward:
    required_observation_names = ("net_electricity_consumption",)

    def calculate(self, observations):
        return [-sum(o["net_electricity_consumption"] for o in observations)]

    The alias required_observations and method get_required_observation_names() are also supported. If a custom reward does not declare requirements, CityLearn falls back to full include_all observations for backward compatibility.

    Macro-Steps / Action Repeat

    step_many() repeats one selected action across multiple internal simulator steps and returns one macro transition for RL replay buffers:

    obs, rewards, terminated, truncated, info = env.step_many(
    action,
    repeat_steps=20,
    stop_on_done=True,
    return_substeps=False,
)

    The simulator still advances every internal step at seconds_per_time_step resolution. Constraints, EV charging/departures, batteries, deferrables, phases/headroom, rewards, KPIs and render/export time series are updated exactly as they are for repeated step() calls. The returned observation is only the final observation after the executed substeps, and rewards is the per-agent reward sum.

    info["executed_steps"] is always present so RL code can discount macro transitions correctly:

    gamma_macro = gamma ** info["executed_steps"]

    When return_substeps=True, info also includes substep_rewards, substep_infos and substep_actions_applied for debugging. Keep it disabled in long training runs.

    Reading Latest Step Values

    CityLearnEnv stores episode rewards and the three district net-consumption series in preallocated float64 buffers. Accessing a full-history list property (env.rewards, env.net_electricity_consumption, env.net_electricity_consumption_cost, env.net_electricity_consumption_emission) lazily materializes a tracked Python list that extends incrementally per step and detaches before any in-place mutation, so existing [-1] monitoring loops remain O(1) per step while caller edits stay isolated.

    Read the latest value with [-1]. Each read takes constant time per step. Once read, the list is kept for the rest of the episode, so the memory saving of the buffers holds only while nothing reads these properties during the episode. In training loops, use the reward returned by env.step(), as the CityLearn agents do, and read the histories at the end of the episode.

    latest_reward_row = env.rewards[-1]
latest_net_kwh = env.net_electricity_consumption[-1]
latest_cost_eur = env.net_electricity_consumption_cost[-1]
latest_emission_kgco2 = env.net_electricity_consumption_emission[-1]

    CLI

    The CLI needs only CityLearn for its listing commands and for the default agent, the business-as-usual BusinessAsUsualAgent. Training or evaluating a Stable Baselines3 agent also needs stable-baselines3>=2.4, and the bundled SAC and MARLISA agents need the rl extra. Every command works on Python 3.10 or newer.

    citylearn --version
citylearn list_datasets
citylearn list_default_time_series_variables
citylearn simulate data/datasets/my_dataset/schema.json train -e 3
citylearn simulate data/datasets/my_dataset/schema.json evaluate

    simulate writes a training summary (<simulation_id>-train.json), the evaluation files and, with --save_agent, the agent to the output directory, and prints the path of each file it writes. evaluate and train --evaluate write two evaluation files:

    • <simulation_id>-evaluation_v2.csv: the evaluate_v2() table, with the columns cost_function, value, name, level, unit and description, one row per KPI and scope. It holds the community market rows when the scenario has a market, and the *_business_as_usual_* rows. This is the table that the KPI reference and the scorecard describe; read it with pandas.read_csv.

    • <simulation_id>-evaluation.json: the evaluation window and timestamps, the rewards, the actions and the time series, plus the legacy evaluate() KPIs under evaluation. Its format does not change, so existing parsers keep working, but compare controllers with the evaluate_v2() file.

    The business-as-usual rows need a second rollout of BusinessAsUsualAgent on the evaluation window, as evaluate_v2() does in Python. --no_business_as_usual skips it and writes the table without those rows.

    Stable Baselines3 agent

    A Stable Baselines3 agent needs its policy in the agent arguments and the environment wrapped into one flat observation and action vector, which requires a central agent. This command trains SAC for five daily episodes on the first week and evaluates it on the first training episode:

    citylearn simulate citylearn_challenge_2022_phase_all_plus_evs \
  -a stable_baselines3.SAC -ka '{"policy": "MlpPolicy"}' \
  -w citylearn.wrappers.NormalizedObservationWrapper citylearn.wrappers.StableBaselines3Wrapper \
  -ke '{"central_agent": true, "episode_time_steps": 24, "simulation_end_time_step": 167}' \
  -rs 0 -d outputs/sb3_sac -sid sb3_sac train -e 5 --evaluate --save_agent

    Without "policy", the CLI raises a TypeError that shows the argument to add. Use -te start end to evaluate on other windows, such as unseen days.

    To evaluate or keep training a saved model, pass it with -fa and name the algorithm that saved it with -a, for example -a stable_baselines3.SAC -fa outputs/sb3_sac/sb3_sac-agent.zip. Write to another directory with -d: simulate empties its output directory first, so it refuses to run when that directory holds the model to load.

    What the Stable Baselines3 integration supports:

    • Central agent, flat interface. StableBaselines3Wrapper turns the central agent’s observation and action vectors into one Box each. With central_agent=False there is one vector per building, and the wrapper raises an error; for one policy per building, use RLlibMultiAgentEnv.

    • No entity interface. The entity observations are dictionaries of tables whose sizes can change, which the SB3 policies cannot take. The pt_rec_*, three-phase, demand-response and robustness datasets default to the entity interface, so pass "interface": "flat" in -ke (or interface="flat" in Python). Dynamic topology and demand response need the entity interface and cannot be used with SB3.

    • Action bounds. The action space keeps each device’s bounds, for example [-1, 1] for storage and EV chargers and [0, 1] for others, so check_env warns that it is not symmetric. SAC rescales its actions to the bounds and PPO clips them, so both work as they are.

    • Robustness faults. A missing sensor reading is replaced by missing_replacement_value (-9999 in citylearn_challenge_2022_phase_all_robustness), which normalises far outside [0, 1]. SB3 does not check observation bounds, but the policy sees that value as it is.

    tests/test_stable_baselines3_integration.py runs check_env, a few SAC and PPO updates, predict over one episode with every observation inside its space, evaluate_v2(), and the CLI saving and loading a model.

    Evaluation window

    evaluate runs one episode of the environment’s episode windows, or the windows that -te gives. train --evaluate evaluates on the first training episode window: with -ke '{"episode_time_steps": 24}' it evaluates 24 time steps, not the whole dataset. Without episode_time_steps, the episode, and so the evaluation, covers the whole simulation window.

    Render and Export

    render_mode

    Runtime cost

    Output

    Use case

    none

    lowest

    No render CSV

    Training.

    during

    high

    Writes rows each step

    Short debugging runs.

    end

    Long episodes with final CSV output.

    Set render_file_format="parquet" to write render, KPI and BAU time-series exports as chunked parquet part files instead of CSV. render_chunk_size controls the number of rows per parquet part; the default is 50000 for parquet and 100000 for CSV.

    KPI and BAU exports are episode-scoped, so training loops can keep export disabled and turn it on only for the final episode. If normal time-series outputs are needed on that final episode, create the environment with render_mode="end" and toggle render_enabled; for KPI-only output, leave render disabled and call export_final_kpis() manually after the final episode.

    for episode in range(episodes):
    last_episode = episode == episodes - 1
    env.render_enabled = last_episode
    env.export_kpis_on_episode_end = last_episode
    observations, info = env.reset()
    # run episode...

    export_final_kpis() controls the BAU cost separately:

    Call

    Output

    BAU sidecar cost

    env.export_final_kpis(include_business_as_usual=False)

    KPI file and audit metadata

    no

    env.export_final_kpis(include_business_as_usual=True, export_business_as_usual_timeseries=False)

    KPI file with BAU rows and audit metadata

    yes

    env.export_final_kpis(include_business_as_usual=True, export_business_as_usual_timeseries=True)

    For exact final-episode choices, keep export_kpis_on_episode_end=False and call export_final_kpis() yourself after the episode terminates.

    Comparing two exported runs

    export_final_kpis() writes exported_kpis.manifest.json next to the KPI file. compare_exports(left, right) reads two KPI files and their manifests; compare_manifests(left, right) does the same check on manifests already loaded as dictionaries. Both are in citylearn.internal.comparison. They report whether the difference between the two runs can be read as a controller difference:

    status

    Meaning

    'paired'

    Only the controller differs. permitted_claim is 'controller_difference'.

    'incompatible'

    A setting that changes the results differs; it is listed in mismatches.

    'unknown'

    Evidence is missing from a manifest; it is listed in missing_evidence.

    The simulator cannot tell which controller chose the actions, so each run declares it with env.set_experiment_identity(implementation, version, parameters, observation_access='agent_payload'). Without it, two otherwise identical runs compare as status='unknown' with missing_evidence=['controller_identity'].

    Argument

    What it records

    implementation

    The controller’s name, for example its import path. Required.

    version

    The version of the controller code or of its trained weights. Required.

    parameters

    A dictionary with the settings that define this controller. It must be JSON-serializable with finite numbers; use {} when there are none.

    observation_access

    What the controller observes. The default 'agent_payload' is the observations returned by reset() and step(). Two runs with different values are incompatible (controller_observation_access).

    The identity is written to the manifest as controller_identity. It stays on the environment across reset(), so call it once after creating the environment; it must be set before export_final_kpis() runs, including the automatic export at the end of the episode when export_kpis_on_episode_end=True. The rule-based baselines declare their own identity through agent.comparison_identity(): pass the agent to env.export_final_kpis(model=agent) and it is recorded for you, with observation_access='entity_observations'. With MultiCommunityEnv, call it on each community in mc.envs, whose own exports carry the manifests. compare_exports(left, right, mode='sharing') compares one controller with sharing on and off, and also requires the two identities to be equal.

    This example runs one simple controller with two parameter values, exports both runs and compares them:

    from pathlib import Path

from citylearn.citylearn import CityLearnEnv
from citylearn.internal.comparison import compare_exports


def run(name, battery_action):
    env = CityLearnEnv(
        "citylearn_challenge_2022_phase_all_plus_evs", central_agent=True, episode_time_steps=24,
        render_directory="runs", render_session_name=name, export_kpis_on_episode_end=False,
    )
    env.set_experiment_identity(
        implementation="my_project.ConstantBattery", version="1.0",
        parameters={"battery_action": battery_action},
    )
    env.reset()
    while not env.terminated:
        actions = [[battery_action if n.startswith("electrical_storage") else 0.0 for n in env.action_names[0]]]
        env.step(actions)
    env.export_final_kpis(export_business_as_usual_timeseries=False)
    path = Path(env.new_folder_path) / "exported_kpis.csv"
    env.close()
    return path


report = compare_exports(run("idle", 0.0), run("charge", 0.2))
print(report["status"], report["missing_evidence"], report["mismatches"])

    Smoke-Test a Large Dataset

    For large 15s datasets, always run a short window first:

    python - <<'PY'
import numpy as np
from citylearn.citylearn import CityLearnEnv

env = CityLearnEnv(
    "citylearn_three_phase_electrical_service_demo_15s_parquet",
    simulation_start_time_step=0,
    simulation_end_time_step=120,
    episode_time_steps=120,
)
obs, info = env.reset()
for _ in range(100):
    if isinstance(env.action_space, list):
        actions = [np.zeros(space.shape, dtype="float32") for space in env.action_space]
    else:
        actions = {
            "tables": {
                name: np.zeros(space.shape, dtype="float32")
                for name, space in env.action_space["tables"].spaces.items()
            }
        }
    obs, reward, terminated, truncated, info = env.step(actions)
    if terminated or truncated:
        break
print(env.evaluate_v2().head())

    Validation from a Source Checkout

    The test suite and the audit scripts are in the repository, not in the package that pip install citylearn installs. Run them from a clone, with the test requirements installed (see the developer guide and the validation guide):

    python -m pytest -q
python scripts/audit/audit_entity_contract.py --strict
python scripts/audit/audit_physics.py
python -m ruff check citylearn tests scripts/manual scripts/ci

    KPI-only exports include a manifest and service-audit JSON sidecars. They do not enable episode time-series output; CityLearn UI can load the folder as before. The manifest identifies input files by their path below the dataset root; Portable experiment evidence lists which spellings of a file reference record the same evidence.
