    Schema Reference

    This page documents the schema.json contract. The schema is the source of truth for buildings, devices, EVs, deferrable appliances, escalators, interfaces, observation bundles, demand response, robustness, dynamic topology and local market configuration.

    General Rules

    Rule

    Contract

    Paths

    Relative paths are resolved from root_directory; absolute paths are allowed.

    Tabular files

    CSV and Parquet are interchangeable when columns and units are equivalent.

    Energy

    Dataset energy series are kWh/step.

    Power and limits

    Power ratings and limits are kW.

    Prices

    Prices are per kWh.

    Emissions

    Carbon intensity is kgCO2/kWh.

    Timesteps

    Windows, deadlines and topology events use global simulation timestep indices.

    Legacy washing machines

    washing_machines and washing_machine_energy_simulation are not the official format. Use deferrable_appliances.

    Calendar and dataset metadata keys

    These keys describe the dataset clock and its provenance; the Portugal REC schemas (pt_rec_*) use several of them. The first five change how the dataset clock is read; the others are descriptive metadata that the simulator does not read, kept so a dataset can be traced to its source.

    Key

    Type

    Effect

    time_axis.calendar_file

    string

    Canonical calendar with the columns time_step and timestamp_utc (and optionally timestamp_local), one regular row per dataset row. It sets the dataset step and the timestamps of rendered and exported series, unless start_date is passed to CityLearnEnv.

    timezone

    string

    IANA time zone of the calendar, e.g. Europe/Lisbon. Exported timestamps are converted from UTC to this zone; an unknown name raises an error at load time. Without a calendar it is only recorded.

    dataset_seconds_per_time_step

    number

    Declared dataset step in seconds, for data whose calendar columns cannot give it. It must agree with the calendar.

    dataset_contract_version

    string

    Version of the dataset’s data contract. A value starting with portugal-native makes shared/calendar.parquet the calendar when time_axis is absent; otherwise it is metadata.

    terminal_observation_padding

    bool

    Allows the files to stop one row short of the window and repeats the last row as the terminal observation only, which is never simulated. Default false.

    dataset_id, dataset_family

    string

    Metadata: dataset identifiers.

    experimental_design

    object

    Metadata: the evaluation design the dataset was built for (factors, purpose, labels).

    native_compatibility

    object

    Metadata: the engine commit and checks the dataset was validated with.

    _derivation, _derived_from

    object/string

    Metadata: how a derived dataset was produced from its source.

    generation_mode

    Aliases

    Interprets energy_simulation.solar_generation as

    Formula

    per_kw

    profile, w_per_kw

    Normalized profile per installed kW in W/kW.

    generation_kwh = nominal_power * value / 1000 * seconds_per_time_step / 3600.

    absolute

    absolute_kwh, kwh, kwh_step, energy

    Absolute generation already in kWh/step.

    generation_kwh = value.

    Use absolute for real measured generation or converter-generated energy series. Use per_kw for normalized PV profiles.

    For example, nominal_power=4.0 and a value of 1000 W/kW give 4.0 kWh per hourly step and 1.0 kWh per 900 s step.

    Battery

    "electrical_storage": {
  "type": "citylearn.energy_model.Battery",
  "attributes": {
    "capacity": 6.4,
    "nominal_power": 5.0,
    "efficiency": 0.9,
    "depth_of_discharge": 0.9,
    "initial_soc": 0.1,
    "capacity_loss_coefficient": 1e-5,
    "loss_coefficient": 0.0,
    "power_efficiency_curve": [[0, 0.83], [0.3, 0.83], [0.7, 0.9], [0.8, 0.9], [1, 0.85]],
    "capacity_power_curve": [[0.0, 1.0], [0.8, 1.0], [1.0, 0.2]]
  }
}

    The stationary battery model works on energy per control step at the battery terminals, the building side of the battery. The state of charge (SOC) is a fraction of capacity.

    Attribute

    Unit

    Default

    Meaning

    capacity

    kWh

    0

    Rated storage capacity, before fade.

    nominal_power

    kW

    0

    Power that the curves scale.

    efficiency

    ratio

    drawn in [0.90, 0.98]

    Round-trip efficiency. A generated power_efficiency_curve is built around it; during the simulation the curve gives the efficiency at each step.

    power_efficiency_curve

    [[x, y], ...]

    drawn, see below

    Round-trip efficiency y against terminal power divided by nominal_power (x in [0, 1]).

    capacity_power_curve

    [[x, y], ...]

    drawn, see below

    Maximum charging power as a fraction of nominal_power (y) against SOC (x).

    discharge_power_curve

    [[x, y], ...]

    [[0, 1], [1, 1]]

    Maximum discharging power as a fraction of nominal_power against SOC. Physics version 1 uses capacity_power_curve instead.

    depth_of_discharge

    ratio

    1.0

    Fraction of capacity that may be discharged.

    initial_soc

    ratio

    1 - depth_of_discharge

    SOC at the start of the episode, in [0, 1].

    capacity_loss_coefficient

    ratio

    drawn in [1e-5, 1e-4]

    Fraction of capacity lost per equivalent full cycle.

    loss_coefficient

    ratio per hour

    drawn in [0.001, 0.009]

    Standby loss of the stored energy, see EV definitions for the per-step formula.

    A default shown as “drawn” is taken from the environment’s random stream when the attribute is omitted, so it depends on the seed and on random_stream_version. The 2022 challenge datasets omit both curves, so each seed gets different curves. Set the attributes explicitly to fix them.

    • Efficiency. efficiency and every value of power_efficiency_curve are round-trip efficiencies: energy charged and later discharged keeps efficiency of its value. Each conversion uses the square root. Charging E kWh at the terminals stores E * sqrt(eta), and delivering E kWh takes E / sqrt(eta) from storage, where eta is read from power_efficiency_curve at the applied terminal power. A datasheet one-way efficiency of 0.95 must be entered as 0.95² = 0.9025; entered as 0.95, it gives a one-way efficiency of about 0.975.

    • Power curves. capacity_power_curve and discharge_power_curve are evaluated at the SOC at the start of the step, and their values are multiplied by nominal_power. Between points the curves are interpolated linearly.

    • Depth of discharge. Discharging stops at a SOC of 1 - depth_of_discharge, a floor measured on the rated capacity. Charging stops at the degraded capacity.

    • Capacity fade. After each charge or discharge the capacity falls by capacity_loss_coefficient * capacity * |terminal energy| / (2 * degraded capacity). A full charge and discharge of the degraded capacity is one equivalent full cycle and loses capacity_loss_coefficient * capacity.

    • Generated curves. Without power_efficiency_curve, five points are drawn at x near 0, 0.3, 0.7, 0.8 and 1, with values between 0.85 and 1.0 times efficiency (the point near 0.8 equals efficiency). Without capacity_power_curve, three points are drawn: 0.95 to 1.0 at SOC 0, 0.90 to 0.95 at a SOC near 0.8, and 0.20 to 0.30 at SOC 1.

    • With the default initial_soc, a battery starts at its reserve: empty when depth_of_discharge is 1. Set initial_soc to start elsewhere.

    Available grid power

    available_grid_power names a CSV or Parquet file with one row per time step, aligned with energy_simulation. Give it as a file name or as {"filename": ..., "column": ...}. Without column, the column named after the building is used, then a column named available_grid_power, so one file can hold a column per building. Values are the grid power the building may import at that step, in kW (power, not energy per step).

    The import limit in force at a step is the smaller of limits.total.import_kw and the series value. A blank value applies the static limit only; it is an error when import_kw is not set. Values must be finite and non-negative. Use it for curtailment below the connection capacity, such as a distribution system operator dimming controllable devices (German §14a EnWG) or a capacity reduction during grid stress.

    The limit acts like the static one: EV chargers and the electrical storage are curtailed first, and load that cannot be curtailed is still served and counted as an electrical-service violation. A limit of 0 kW does not island the building; use power_outage for a blackout. Per-phase limits stay static. The available_grid_power observation reports the limit for the coming interval; the headroom observations describe the last executed interval, so they reflect the limit that was in force then.

    battery.attributes

    Battery kwargs.

    EV battery standby loss is intentionally isolated from stationary storage defaults:

    • Missing or null battery.attributes.loss_coefficient defaults to 0.0 for EVs.

    • Explicit EV loss_coefficient values are interpreted as hourly loss ratios.

    • All StorageDevice implementations, including stationary Battery and StorageTank, convert hourly loss_coefficient values to an effective per-step loss compounded over the step: 1 - (1 - loss_coefficient) ** (seconds_per_time_step / 3600).

    • Stationary storage default parameter ranges are unchanged.

    A member’s time-series files (energy simulation, chargers, escalators) are either full-horizon, with one row per dataset time step, or member-window files, shorter than the dataset, whose first row is the time step of the member’s add_member event.     Community Market

    "community_market": {
  "enabled": true,
  "local_price_ratio_to_grid_import": 0.8,
  "import_member_weights": {
    "Building_1": 1.0,
    "Building_2": 2.0
  },
  "kpis": {
    "community_local_traded_enabled": true,
    "community_self_consumption_enabled": true
  }
}

    Field

    Default

    Purpose

    enabled

    false

    Enables local settlement.

    local_price_ratio_to_grid_import

    0.8

    Local price relative to grid import price. A number from 0 to 1.

    intra_community_sell_ratio

    alias

    Legacy name for the same ratio. If both keys are set, they must be equal.

    settlement_version

    1

    1 or 2, as a number (2.0 is accepted, the string "2" is not). 2 enables grid_export_price; with 1, residual grid exports earn nothing.

    grid_export_price

    0.0

    EUR/kWh paid for residual grid exports. A finite number; a non-zero value requires "settlement_version": 2.

    tariff_files

    {}

    Per-member CSV tariffs, {"<building>": "<file inside the dataset>"}. Each file has one row per global time step with grid_export_price, community_buy_price and community_sell_price (EUR/kWh) and must cover the episode. A member with a file uses these prices instead of the ratio and grid_export_price.

    local_trading_enabled

    true

    false keeps the market’s settlement and KPIs but trades no energy locally. Booleans or "true"/"false".

    import_member_weights

    {}

    Weights for allocating local energy among importers, {"<building>": weight}. Each building must be in the schema and each weight a finite number of at least 0.

    kpis.community_local_traded_enabled

    true

    Enables local traded energy KPI.

    kpis.community_self_consumption_enabled

    true

    Enables local import-share KPI.

    matching_granularity

    "aggregate_building"

    The only supported value; recorded in the metadata.

    counterfactual

    "grid_only"

    The only supported value: savings compare each member with buying and selling on the grid alone. Written by the annual REC suite generator.

    Important Combinations

    The settings are checked when the env is built, even with enabled: false. An unknown key (for example enable), a ratio that is not a number or is outside [0, 1], a settlement_version other than 1 or 2 (the string "2" included), a non-zero grid_export_price without "settlement_version": 2, and a member weight or tariff file for a building that is not in the schema raise a ValueError. Earlier releases ignored these settings or replaced them with defaults. The legacy intra_community_sell_ratio key is an alias.

    The settings are read from the schema at construction. Setting the market attributes on the env afterwards (community_market_enabled, community_market_sell_ratio, community_market_grid_export_price, community_market_import_member_weights, community_market_local_enabled, community_tariffs) is not supported: the native BAU reference is rebuilt from the schema, so evaluate_v2() with the BAU comparison raises a ValueError when they differ. To change the market, edit schema['community_market'] and build a new env. Local settlement values same-timestep member imports and exports; it does not change the physical device dispatch.

    Each side of a local trade is priced with its own member’s tariff. When members have different grid tariffs or tariff_files, importers can pay a different amount from what exporters receive for the same energy. The difference is reported as community_operator_balance_total_eur (positive when the market keeps money); it is zero with a single shared tariff.

    Case

    Configuration

    Classic flat training

    Omit interface or use interface="flat"; static topology.

    Entity/GNN/Transformer

    interface="entity" plus desired observation bundles.

    Dynamic topology

    interface="entity", topology_mode="dynamic", topology_events.

    Demand response

    interface="entity", demand_response.enabled=true, entity_demand_response bundle.

    Robustness

    Any interface, robustness.enabled=true; add entity_robustness for entity diagnostics.

    Real PV measurements

    pv.attributes.generation_mode="absolute".

    15-second data

    seconds_per_time_step=15 and files already at that cadence.

    Large datasets

    Prefer Parquet paths with the same columns.
