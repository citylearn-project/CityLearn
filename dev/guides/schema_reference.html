    How a schema is organised

    Levels

    schema.json
├── root: data location, seeds, time window, episodes, versions, interface, reward, outputs
├── observations: {name: {active, shared_in_central_agent}}        (catalogue for every building)
├── actions: {name: {active}}                                      (catalogue for every building)
├── observation_bundles, derived_forecasts                         (entity interface only)
├── buildings
│   └── <building>: data files, type, inactive_observations/actions, equity_group
│       ├── cooling_device, heating_device, dhw_device              (HVAC devices)
│       ├── cooling_storage, heating_storage, dhw_storage           (thermal storage)
│       ├── electrical_storage, pv                                  (battery, PV)
│       ├── chargers: {<charger_id>: type, charger_simulation, attributes, ...}
│       ├── deferrable_appliances, escalators
│       ├── electrical_service | charging_constraints              (grid connection limits)
│       └── power_outage, dynamics, occupant, set_point_*
├── electric_vehicles_def: {<ev_id>: type, include, battery}
├── community_market, demand_response, robustness                  (community services)
└── topology_mode, topology_events                                 (members and assets that change)

    Loading a schema

    CityLearnEnv(schema) accepts three forms, which treat root_directory differently.

    Form

    Example

    root_directory

    Path to a JSON file or to a folder containing schema.json

    CityLearnEnv("data/my_dataset/schema.json")

    Optional. null or missing: the schema’s folder. Absolute: used as is. Relative: resolved from the schema’s folder, then from its parent folders.

    Name of a public dataset

    CityLearnEnv("citylearn_challenge_2022_phase_all_plus_evs")

    Replaced by the folder that DataSet().get_dataset(name) returns, whatever the schema says: a complete local copy, cached under a digest of its files, or else a download of the release.

    Python dict

    CityLearnEnv(schema_dict)

    Required key. null means the current working directory, so relative file names are read from there.

    Every file name in the schema (energy_simulation, charger_simulation, requests_file, …) is resolved from root_directory unless it is absolute. The root_directory argument of CityLearnEnv replaces the schema value for every file except community_market.tariff_files, which is always resolved from the schema’s own root_directory.

    Schema keys and constructor arguments

    A CityLearnEnv argument that is not None replaces the schema value of the same name, and the schema value replaces the built-in default. Constructor arguments lists every pair. Exceptions:

    • render_mode and render: a value in the schema wins over the argument.

    • topology_mode="static" cannot override a schema that declares dynamic topology or contains topology_events; it raises ValueError.

    • start_date given in the schema is ignored when the dataset has a calendar (time_axis.calendar_file); the argument is not.

    • The constructor changes a copy of the schema: env.schema keeps the values of the file, not the effective values. Read the effective ones from the env (env.physics_version, env.seconds_per_time_step, …) or env.get_metadata().

    An unknown constructor argument raises TypeError with the closest valid name. An unknown root key in the schema is ignored without a warning.

    General rules

    Rule

    Contract

    Paths

    Relative paths are resolved from root_directory; absolute paths are allowed (tariff files must be inside the dataset).

    Tabular files

    CSV and Parquet (.parquet, .pq, .parq) are interchangeable when the columns and units are the same. Community tariff files are CSV only.

    Energy

    Dataset energy series are kWh per dataset step.

    Power and limits

    Power ratings and limits are kW.

    Prices

    Prices are per kWh, in the currency of the dataset (EUR in the market KPIs).

    Emissions

    Carbon intensity is kgCO2/kWh.

    Time steps

    Windows, deadlines and event times are global data-row indices (row 0 is the first row of the files), inclusive at both ends.

    null

    In device and charger attributes, null means “use the default” (including drawn defaults).

    Booleans

    Write JSON true / false. Most keys also accept 0/1 and the strings "true"/"false", but some keys treat any non-empty string as true; see Common mistakes.

    Ranges

    Device attributes documented as “drawn” accept a number or null. A [low, high] range raises TypeError.

    Legacy washing machines

    washing_machines is not read (a schema with it loads without the appliances). Use deferrable_appliances.

    Time window and control step

    Key

    Type

    Default

    Unit / values

    Effect

    Argument

    Since

    seconds_per_time_step

    number

    required

    s, at least 1

    Duration of one control step. Must equal the dataset step unless time_step_ratio_mode is compress.

    seconds_per_time_step

    original

    simulation_start_time_step

    int

    required

    data row

    First row read from every time-series file.

    simulation_start_time_step

    original

    simulation_end_time_step

    int

    required

    data row

    Last row read, inclusive. The window has end - start + 1 rows; rows outside it are not loaded. It must be a row of every time series file: a later value raises ValueError at construction that names the file and the last valid end step (one more with terminal_observation_padding).

    simulation_end_time_step

    original

    time_step_ratio_mode

    string

    reject

    reject, compress

    What to do when seconds_per_time_step differs from the dataset step. reject raises ValueError. compress keeps the 3.6.0 behaviour: one data row per control step, energies scaled by the ratio, and a notice is printed.

    time_step_ratio_mode

    after 3.6.0

    The dataset step is read, in this order, from dataset_seconds_per_time_step, from the calendar file, or from the hour, minutes and seconds columns of energy_simulation (at least 90 % of the intervals must agree). time_step_ratio is a constructor argument only: if given, it must match the inferred ratio.

    To get 15-minute control on 15-minute data, set "seconds_per_time_step": 900. To simulate one week of an hourly dataset, set "simulation_start_time_step": 0 and "simulation_end_time_step": 168 (169 rows, 168 control steps).

    Episodes

    Key

    Type

    Default

    Values

    Effect

    Argument

    Since

    episode_time_steps

    int, list of [start, end], null

    null

    null: one episode covering the whole window. An int N: episodes of N rows (N - 1 control steps). A list: explicit episodes, both ends inclusive.

    episode_time_steps

    original

    rolling_episode_split

    bool

    false

    With an int episode_time_steps, every row from the window start to end + 1 - N is a possible episode start (overlapping windows). Ignored for a list.

    rolling_episode_split

    original

    random_episode_split

    bool

    false

    Pick the episode at random at every reset (with replacement), seeded by random_seed and the episode number. Without it, episodes are used in order and cycle. Applies to int and list episodes.

    random_episode_split

    original

    episode_split_boundary

    string

    shared

    shared, disjoint

    For non-rolling int episodes. shared: the last row of an episode is the first row of the next, so every interval is simulated (stride N - 1). disjoint: the 3.6.0 splits (stride N), which skip the interval between two episodes.

    episode_split_boundary

    after 3.6.0

    ev_soc_carryover

    bool

    false

    Start each EV of an episode that continues the previous one in time (on its last row with shared, on the row after it with disjoint) from its SOC at the end of that episode, instead of the schedule SOC. Sequential splits and explicit lists carry; random and rolling splits never do. Only the EV SOC is carried. See the migration guide.

    ev_soc_carryover

    after 3.6.0

    Rules:

    • An episode of N rows has N - 1 control steps: the last row is only the terminal observation.

    • An int N must be between 1 and the window length; a trailing window shorter than N is dropped. With shared, N must be at least 2 when there is more than one episode.

    • Each [start, end] must satisfy 0 <= start <= end and lie inside the simulation window; otherwise ValueError. Write a JSON list of lists: a Python tuple of pairs raises TypeError.

    • If a simulation_*_time_step argument narrows the window, the schema’s episode list is clipped to it and episodes left empty are dropped.

    • env.reset(options={"episode_index": k}) selects episode k directly.

    Recipes:

    {"episode_time_steps": 169, "rolling_episode_split": false, "random_episode_split": true}

    gives one-week episodes (168 steps) that share their boundary rows, drawn at random at each reset.

    {"episode_time_steps": [[0, 2159], [2160, 4319], [4320, 6479]]}

    gives three fixed episodes used in turn.

    These keys describe the dataset clock. They change how timestamps and the dataset step are read, not the physics.

    Key

    Type

    Default

    Effect

    Since

    time_axis.calendar_file

    path

    none

    string

    terminal_observation_padding

    bool

    false

    Lets every time-series file stop exactly one row short of the window: the last row is repeated as the terminal observation only (its calendar fields advance by one step, and a connected EV that departs is shown as gone).     YYYY-MM-DD

    Date of global row 0 in rendered and exported timestamps when there is no calendar. It does not change the simulation.

    Versions

    Three version keys select behaviour that changed after CityLearn 3.6.0. Each accepts an int, an integral float or a digit string (2, 2.0, "2"); a boolean raises ValueError. The constructor argument of the same name wins. What each version changes lists every difference.

    Key

    Values

    Default

    Selects

    Since

    physics_version

    1, 2

    2

    Device and dispatch physics. 1 reproduces CityLearn 3.6.0.

    after 3.6.0

    baseline_version

    1, 2

    2

    Definition of the KPI baseline (*_without_storage series) and of the BAU HVAC. 1 as in 3.6.0: nothing added back, and the BAU sends zero to the HVAC actions. 2 adds back the BAU EV charging, and on datasets with HVAC actions the BAU delivers the dataset heating and cooling demand. Any other value raises ValueError. env.baseline_version = v also works after construction.

    after 3.6.0

    random_stream_version

    v1, v2 (also 1, 2, "V2")

    v2

    How random numbers are drawn from random_seed. v1 reproduces 3.6.0.

    after 3.6.0

    The community market has its own settlement_version; see Community market. To reproduce a 3.6.0 result, set physics_version: 1, baseline_version: 1, random_stream_version: "v1", episode_split_boundary: "disjoint" and, for data whose step differs from the control step, time_step_ratio_mode: "compress". See the migration guide.

    A default shown as “drawn” is taken from the environment’s random stream when the attribute is omitted or null, so it depends on the seed and on random_stream_version. The 2022 challenge datasets omit both curves, so each seed gets different curves. Set the attributes explicitly to fix them.

    • Efficiency. efficiency and every value of power_efficiency_curve are round-trip efficiencies: energy charged and later discharged keeps efficiency of its value. Each conversion uses the square root. Charging E kWh at the terminals stores E * sqrt(eta), and delivering E kWh takes E / sqrt(eta) from storage, where eta is read from power_efficiency_curve at the applied terminal power. A datasheet one-way efficiency of 0.95 must be entered as 0.95² = 0.9025; entered as 0.95, it gives a one-way efficiency of about 0.975.

    • Power curves. capacity_power_curve and discharge_power_curve are evaluated at the SOC at the start of the step, and their values are multiplied by nominal_power. Between points the curves are interpolated linearly.

    • Depth of discharge. Discharging stops at a SOC of 1 - depth_of_discharge, a floor measured on the rated capacity. Charging stops at the degraded capacity.

    • Capacity fade. After each charge or discharge the capacity falls by capacity_loss_coefficient * capacity * |terminal energy| / (2 * degraded capacity). A full charge and discharge of the degraded capacity is one equivalent full cycle and loses capacity_loss_coefficient * capacity.

    • Generated curves. Without power_efficiency_curve, five points are drawn at x near 0, 0.3, 0.7, 0.8 and 1, with values between 0.85 and 1.0 times efficiency (the point near 0.8 equals efficiency). Without capacity_power_curve, three points are drawn: 0.95 to 1.0 at SOC 0, 0.90 to 0.95 at a SOC near 0.8, and 0.20 to 0.30 at SOC 1.

    • With the default initial_soc, a battery starts at its reserve: empty when depth_of_discharge is 1. Set initial_soc to start elsewhere.

    • Outages. Under physics version 2 the battery discharges during an outage after the thermal storage, and only up to the islanded load that PV leaves uncovered.

    Available grid power

    available_grid_power names a CSV or Parquet file with one row per time step, aligned with energy_simulation. Give it as a file name or as {"filename": ..., "column": ...}.     Settlement per step

    For the active members at step t, with n_i the net consumption of member i:

    • import_i = max(n_i, 0), export_i = max(-n_i, 0); traded = min(sum import, sum export), or 0 without local trading.

    • Local import of each member: traded is shared among importers in proportion to import_member_weights (default 1), never above a member’s import; what a saturated member cannot take goes to the others. A weight of 0 is served last. Local export: pro rata to each exporter’s export.

    • Prices: grid import price p_imp from the member’s pricing file; local buy and sell price ratio × p_imp; residual export price grid_export_price (0 under settlement version 1). A tariff file supplies the three prices instead.

    • cost_i = (import_i - local_import_i) × p_imp + local_import_i × p_buy - local_export_i × p_sell - (export_i - local_export_i) × p_export.

    • Counterfactual: max(n_i, 0) × p_imp - export_i × p_export; savings are counterfactual minus cost.

    • Operator balance: local_import_i × p_buy - local_export_i × p_sell, summed in community_operator_balance_total_eur (positive when the market keeps money; zero with one shared tariff).

    Each side of a local trade is priced with its own member’s tariff, so with different tariffs importers can pay a different amount from what exporters receive. Settlement changes costs, not the physical dispatch. See the community market KPIs.

    Validation

    The settings are checked when the env is built, even with enabled: false. An unknown key (for example enable), a ratio that is not a number or is outside [0, 1], a settlement_version other than 1 or 2 (the string "2" included), a non-zero grid_export_price without "settlement_version": 2, and a member weight or tariff file for a building that is not in the schema raise a ValueError. Tariff files are also loaded when the market is disabled.

Setting the market attributes on the env afterwards (community_market_enabled, community_market_sell_ratio, community_market_grid_export_price, community_market_import_member_weights, community_market_local_enabled, community_tariffs) is not supported: the native BAU reference is rebuilt from the schema, so evaluate_v2() with the BAU comparison raises a ValueError when they differ. When only one run enables evaluation_window, and both runs otherwise pair (including a controller identity from set_experiment_identity(), see Comparing two exported runs), compare_manifests() keeps status='paired' for all shared KPIs, records 'evaluation_window_one_sided' in declared_differences (evaluation_window.status == 'one_sided'), and compare_exports() flags only the windowed rows in unpaired_window_kpis.

    Demand response

    Demand response is dataset-driven and requires interface: "entity". The agent observes district-level flexibility requests and responds through the physical actions that already exist, such as storage, EVs and flexible loads.

    {"demand_response": {
  "enabled": true,
  "requests_file": "demand_response_requests.csv",
  "baseline_method": "rolling_pre_event_average",
  "baseline_window_seconds": 3600,
  "allow_overlapping_requests": false
}}

    Default

    Purpose

    enabled

    false

    requests_file

    required when enabled

    CSV or Parquet file, absolute or relative to root_directory.

    baseline_method

    rolling_pre_event_average

    The only method: the average net consumption of the active members over the window before the request.

    baseline_window_seconds

    3600

    Length of that window, rounded up to whole steps (at least one step).

    Column

    issuer

    dso/tso

    Entity that issued the request.

    Dynamic topology

    topology_mode: "dynamic" requires interface: "entity". In dynamic mode every building in the schema is loaded; include: false makes a building an inactive member until an add_member event (if every building is inactive, the first one is activated).

    {"topology_events": [
  {
    "id": "add_pv_b2_t100",
    "time_step": 100,
    "operation": "add_asset",
    "target_member_id": "Building_2",
    "target_asset_type": "pv",
    "target_asset_id": "pv_1",
    "source_member_id": "Building_1",
    "source_asset_id": "pv_1",
    "overrides": {"nominal_power": 80.0}
  }
]}

    Field

    Required

    Purpose

    id

    no

    Event ID, unique; default topology_event_<index>.

    time_step

    yes

    Global time step at which the event is applied. Events before the episode start are applied at its first step.

    operation

    yes

    add_member, remove_member, add_asset, remove_asset.

    target_member_id

    yes

    Target building. add_member with a name that is not in the schema clones source_member_id under that name. The clone’s chargers get ids of their own. The source member’s name in the id becomes the target’s; otherwise the identifier that ends the member name (1 in Building_1, 001 in Member_001) is replaced by the target’s at its first standalone occurrence, so charger_1_1 of Building_1 becomes charger_19_1 in Building_19. An id that contains neither, or that would not change, gets _<target member> appended; a clash with another charger adds _2, _3, … Robustness events must name the clone’s chargers by the new id.

    target_asset_type

    asset operations

    charger, deferrable_appliance, pv, electrical_storage.

    target_asset_id

    charger and deferrable operations

    Target asset. Not used for pv and electrical_storage (one per building).

    source_member_id

    no

    Building to clone from; defaults to the target member for asset operations.

    source_asset_id

    no

    Asset to clone; defaults to target_asset_id.

    overrides

    no

    Attributes set on the cloned object; each must exist on it. Ignored for remove operations.

    Adding PV or storage replaces the building’s current one. Removing a deferrable appliance cancels pending/running cycles and clears future consumption. Removing PV creates a zero PV. Removing storage creates a zero BESS. What a replaced or removed PV or battery produced or consumed before the event stays in the building’s series, so the baselines without storage and the district sums keep it (for the battery, from baseline_version 2). A schema with topology_events raises ValueError unless topology_mode is dynamic.

    A member’s time-series files (energy simulation, chargers, escalators) are either full-horizon, with one row per dataset time step, or member-window files, shorter than the dataset, whose first row is the time step of the member’s add_member event. A member-window file should cover the member’s active steps in the simulation window (otherwise its last row is repeated, with a warning), and a member that joins again after leaving needs full-horizon files. A member that joins mid-episode starts its battery and thermal storage at initial_soc.

    Multiple communities

    MultiCommunityEnv has no schema keys of its own. It takes a list of communities, each {"community_id": ..., "schema": ..., "env_kwargs": {...}, "weight": 1.0}; other entry keys raise ValueError. Every community must use the same interface, central_agent, seconds_per_time_step, episode length, physics_version, random_stream_version and baseline_version. render_directory and render_session_name in env_kwargs are replaced by those of the wrapper. See the multi-community reference.

    baseline_version

    Version

    KPI baseline (*_without_storage)

    Native BAU HVAC

    1

    removes battery, thermal storage and EV charging; adds nothing back

    Common mistakes and what to avoid

    Mistake

    What happens

    Do instead

    A typo in a root key (seconds_per_timestep) or in demand_response, robustness, derived_forecasts, observation_bundles

    Ignored; the default is used.

    Check env.get_metadata() and the observation names after construction.

    Writing booleans as strings

    "false" counts as true for rolling_episode_split, random_episode_split, power_outage.simulate_power_outage, stochastic_power_outage and vehicle_to_building.

    Use JSON true / false.

    Leaving random_seed out

    A new seed at every construction; robustness noise and drawn device parameters change.

    Set random_seed.

    Expecting drawn defaults to be the same for different seeds

    Battery curves, efficiencies and loss coefficients are drawn.

    Set the attributes.

    A [low, high] range as an attribute

    TypeError.

    Give a number.

    Activating electrical_storage for a building without a battery

    ValueError at construction.

    List it in that building’s inactive_actions.

    cooling_device / heating_device actions on citylearn.building.Building

    The action exists but does nothing.

    Use a dynamics building type.

    Omitting max_discharging_power and expecting V2G

    Physics version 2 sets it to 0.

    Set it explicitly.

    Charger files with numeric electric_vehicle_id values

    The EV never connects.

    Use text IDs that match electric_vehicles_def.

    A misspelt key in battery.attributes of an EV

    Ignored.

    Compare env.electric_vehicles[i].battery with the schema.

    Setting stochastic_power_outage: true without a model

    Half of the steps are outages.

    Use ReliabilityMetricsPowerOutage.

    Both electrical_service and charging_constraints

    charging_constraints is ignored.

    Use electrical_service.

    set_point_limits, dynamics or occupant on citylearn.building.Building

    Ignored.

    Use the matching building type.

    null for an electrical_service limit

    The simulation treats it as no limit, but the native BAU used by evaluate() and evaluate_v2() raises TypeError.

    Leave the key out for no limit.

    render_mode in the schema and another value as argument

    The schema wins.

    Set it in one place.

    Changing env.community_market_* after construction

    evaluate_v2() raises.

    Edit schema["community_market"] and build a new env.

    price_source or load_pv_method left at the default for a benchmark

    The agent reads future prices or loads.

    Use daily_persistence or publication_aware_day_ahead_market_input.

    Non-zero noise_std for a building without pricing or carbon_intensity

    Random prices or emissions appear.

    Add the files or keep noise_std at 0.

    Passing electric_vehicles=[...] to select EVs

    Ignored.

    Use electric_vehicles_def.<ev>.include.

    EV batteries above 100 kWh with connected_electric_vehicle_at_charger_battery_capacity

    The observation exceeds its space bound.

    Normalise by the capacity, or leave it inactive.

    An attribute that a built-in reward does not use, such as a misspelt exponant

    TypeError at construction, with the closest valid name. Rewards defined outside citylearn.reward_function still receive unknown keys.

    Fix the name, or remove the key.

    request_purposes written as a list

    AttributeError when the requests are loaded.

    Write an object, {"<request_id>": "service"}.

    Non-integer or negative start_time_step / end_time_step in a demand-response request file

    Decimals are truncated with int() (3.7 becomes 3), and negative values are accepted.

    Write whole, non-negative data-row indices.

    Per-device names (electric_vehicle_storage_<charger>, per-charger observations) in inactive_actions or the active_/inactive_observations arguments

    Static and dynamic topology treat them differently. Static topology ignores expanded per-device names in inactive_actions; dynamic topology honours them, but recomputes the charger, deferrable-appliance and battery observation flags from the schema, ignoring the active_/inactive_observations arguments and the building’s inactive_observations.

    Turn device features on or off with the catalogue names in observations and actions, and check env.observation_names and env.action_names.
