Validation and performance

Use this page to select a check and understand the scope of published results. For interpreting an ordinary simulation, start with the scorecard and KPI reference.

Run checks from a source checkout

Install the development dependencies as described in the developer guide. Write generated reports to a separate output directory:

python scripts/audit/run_full_audit.py --strict --output-dir /tmp/citylearn-audit

This verifies physical scenarios, entity contracts, bounded probes of the public datasets and fixed-command regression references. Failed or missing checks fail verification; expected results are not regenerated by an ordinary run.

Published validation and measured improvements

The 3.1.0 release notes retain the functional changes, validation counts, benchmark protocol and measured before/after values. They distinguish the corrected functional baseline from the original 3.0.2 release. Older measurements remain in the release archive.

Bounded tests and integration benchmarks do not establish annual validation of every dataset, controller performance or calibration against real equipment. Reproduction requires matching inputs, parameters, runtime and validation scope. See the migration guide before comparing versions.
