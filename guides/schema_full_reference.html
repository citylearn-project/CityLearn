    Full Reference Schema

    examples/schema_full_reference.json is a complete schema that writes out every option CityLearn reads. It runs as it is from a source checkout: it uses two buildings (Building_1 and Building_4) and two EVs of the citylearn_challenge_2022_phase_all_plus_evs dataset. Copy it, point root_directory at your data and change only what you need.

    from citylearn.citylearn import CityLearnEnv

env = CityLearnEnv("examples/schema_full_reference.json")

    JSON has no comments, so this page walks through the file section by section. Each block below is a part of the file (together they are the whole file), followed by what each key does, its default and its alternatives. The schema reference has the full rules.

    How to read the values:

    • Where a key has a default, the file uses it. A null in device, charger and EV attributes means “use the default”, including defaults drawn from the random stream.

    • Required keys without a default (file names, sizes, the time window) use the dataset’s values.

    • Features that are off by default (community market, demand response, robustness, outages, dynamic topology) are written out with enabled: false or empty lists, so you can see their shape and turn them on.

    • The selection of active observations and actions is an example; every name is false by default.

    Data location, seeds and versions

    {
  "root_directory": "../data/datasets/citylearn_challenge_2022_phase_all_plus_evs",
  "random_seed": 2022,
  "random_stream_version": "v2",
  "physics_version": 2,
  "baseline_version": 2
}

    Key

    Here

    Default

    Notes and alternatives

    root_directory

    dataset folder, relative to the schema file

    the schema’s folder

    Every file name below is read from here. A dict schema must set it. The root_directory argument overrides it.

    random_seed

    2022

    a new random seed at each construction

    Set it for repeatable runs: drawn device parameters, EV initial SOC and drift, noise and random episodes depend on it.

    random_stream_version

    "v2"

    "v2"

    "v1" reproduces the random draws of CityLearn 3.6.0.

    physics_version

    2

    2

    1 reproduces the physics of 3.6.0; see What each version changes.

    baseline_version

    2

    2

    1: the KPI baseline adds no EV charging back, and the BAU sends zero to the HVAC actions, as in 3.6.0. This dataset has no HVAC actions, so its BAU is the same under both versions.

    Observations

    Every observation name CityLearn accepts in the catalogue is listed, except occupant_interaction_indoor_dry_bulb_temperature_set_point_delta, which exists only for the occupant building type: a name that a building cannot produce raises KeyError at construction, even when it is not active. active (default false) turns a name on for every building that can produce it; shared_in_central_agent (default false) puts it once in the central vector when central_agent is true. This file turns on a small example set and marks calendar, weather, price and carbon names as shared, because they are the same for every building.

    Action

    Here

    Range and meaning

    cooling_or_heating_device, cooling_device, heating_device

    off

    HVAC control; effective only for dynamics building types.

    cooling_storage, heating_storage, dhw_storage

    off

    Charge (positive) or discharge (negative) the thermal storage.

    electrical_storage

    on

    [-1, 1] × battery nominal_power.

    electric_vehicle_storage

    on

    One action per charger: [-1, 1] × max_charging_power / max_discharging_power.

    deferrable_appliance

    on

    One action per appliance: start the next cycle above trigger_threshold.

    escalator

    off

    One action per escalator: standby, slow or normal.
