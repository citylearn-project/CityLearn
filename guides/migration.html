Moving an existing project to CityLearn v3

Both the distribution and import name are citylearn. Install it from PyPI, or use the developer guide for a repository checkout.

Keep the controller loop explicit

observations, info = env.reset(seed=0)
observations, rewards, terminated, truncated, info = env.step(actions)

Stop at terminated or truncated. info is the last return value, not the third. The flat interface retains one observation/action vector per building, or one combined vector with central_agent=True. Read action and observation order from the environment rather than hard-coding positions.

Choose the interface and timestep

Start fixed-membership controllers with interface="flat". Use interface="entity" for identified entity tables, relational edges and dynamic membership. Entity observations are an input representation; a GNN or Transformer policy must still be supplied by the user.

Match seconds_per_time_step to the data cadence. Energy columns use kWh/step; power limits use kW. See the unit contract.

Choose the evaluation API

evaluate() retains legacy cost-function names. evaluate_v2() returns the structured KPI names used by the current exports and scorecard. The v2 in the method name denotes the KPI interface, not CityLearn version 2.

The scorecard distinguishes the conventional counterfactual baseline from the native business-as-usual controller and explains service, target accuracy and requested/applied electrical-limit indicators.

Resolve public and local data separately

Public dataset names are resolved against the installed package’s release tag. Use DataSet().get_dataset_names() to see that version’s catalogue (import DataSet from citylearn.data). Supply your own local schema and files for data that are not in the public catalogue; a repository-relative path is not created by pip install.

The release history retains version-specific changes and the development-line history.

Upgrade from 3.2.0 to 3.3.0

No dataset, schema or export-file migration is required.

  • NumPy 2 and Python 3.12+: numpy<2 and scikit-learn<=1.2.2 are no longer pinned. The occupant models of the Quebec datasets are read from their pickles without scikit-learn and evaluated with NumPy, giving predictions bit-identical to scikit-learn 1.2.2; loading them no longer runs code from the file. Arithmetic whose type NumPy 2 changed (NEP 50 promotion of float32 scalars with Python numbers) is written to give NumPy 1’s result, so observations, rewards and simulated time series are identical on both versions. KPIs can differ in the last binary digits (relative differences of order 1e-15): NumPy 2.3 and later add up more than 8,192 values in a different order, which affects totals over episodes longer than 8,192 time steps and the district Gini ratio of more than 90 members, and the equity audit’s Gini ratio uses a BLAS dot product, whose last digit depends on the BLAS build and CPU.

  • Custom occupant models: RandomForestClassifier and DecisionTreeClassifier pickles are read the same way, with any pickle protocol (0 to 5) and when the model was fitted with a numpy.random.RandomState as random_state. Predictions are those of the scikit-learn release that saved the model. Best-split decision trees from 1.3, random forests from 1.4 and random-split decision trees from 1.6 route missing (NaN) inputs using missing_go_to_left. Older versions of each estimator reject those inputs, as do models with monotonic constraints saved with scikit-learn 1.4 through 1.8. Other pickled models are unpickled with the installed scikit-learn. If it cannot read one saved with scikit-learn 1.2.2 or earlier, install scikit-learn==1.2.2 with numpy<2 (Python 3.11 or older), or refit the model and save it with the installed release.

  • Experiment evidence: KPI-export manifests written on Windows record input files and the engine source as on Linux and macOS (file paths below the dataset root with /, engine source hashed with LF line endings), so Windows exports of one dataset pair across locations and their hashes can be checked against the committed files. Linux and macOS evidence is unchanged. Runs on different operating systems still do not pair: engine.runtime_versions records the OS. Portable experiment evidence lists the file-reference spellings that are normalised and how to update a checkout made before .gitattributes.

  • RL agent keyword: pass action_scaling_coefficient= to SAC, MARLISA and other RLC agents. The misspelled action_scaling_coefficienct= still works with a DeprecationWarning; before, only the misspelling took effect.

  • Native BAU reference check: evaluate_v2() raises a ValueError naming the setting when the reference, which is rebuilt from the schema and the constructor arguments, differs from the evaluated env as captured at its last reset(): the building order, a building’s simulate_power_outage or active actions, or any parameter of its devices (heat pumps, heaters, storage tanks, PV, batteries, chargers, appliances and EV batteries), not only battery capacities. Before, the reference silently simulated the schema’s values. A change made after reset() is not detected. Evaluate with include_business_as_usual=False in that case.

  • Dataset downloads: DataSet.get_dataset(name, directory=...) copies the dataset into directory/<name> and returns that schema path. Failed downloads raise instead of being cached, and concurrent first downloads no longer interfere, including when they replace a cache folder missing schema.json. filelock, already installed with torch, is now a declared requirement.

  • SAC and MARLISA: default schedules now work on episodes shorter than the default batch; inconsistent given values raise ValueError instead of assert False. Runs are repeatable from the environment seed. Agents saved with 3.2.0 resume training: the random streams they lack are derived from their seed. MARLISA fills in missing scikit-learn parameters using the installed defaults and refits its demand model on its whole buffer at the first update.

Fixes that change results where they apply:

  • Storage activation and EV topology: the discharge reserve limits energy leaving a battery. A newly activated battery uses its configured initial SOC, including below the reserve. Removing or moving a charger preserves EV identity. While the EV is away, standby losses and seeded mobility continue to apply. A newly activated EV starts from its configured SOC, and an explicit arrival estimate is accounted for as external energy. Exports identify the charger that actually served the EV.

  • Stochastic power outages: built-in models without an explicit seed now derive one from the environment seed, episode window and building name. The native BAU reference uses the same seed and outage signal.

  • Agents: MARLISA’s coordinated actions use each building’s own policy; TabularQLearning bootstraps on the best next-state value; an explicit action_scaling_coefficient now takes effect (the default stays 0.5).

  • KPI references: the native BAU reference re-applies simulate_power_outage, solar_generation and active/inactive action and observation overrides, to the same buildings when buildings= lists them in another order than the schema; with the community market enabled, legacy cost and the equity audit settle the counterfactual too. Autosized equipment in the reference is sized over the same data as the evaluated env, not only the current episode: evaluate_v2() no longer fails on the tx, vt and ca neighbourhood datasets when episodes are shorter than the data, and BAU KPIs of the 2020 and 2021 challenge datasets change because their reference heat pumps and storage now match.

  • Equipment: autosized batteries simulate their datasheet efficiency (tx, vt and ca neighbourhood datasets), and an EV connects to at most one charger per step, which affects charger clones in the dynamic-topology demos.

  • EV datasets: each EV draws its own unspecified battery parameters (efficiency, curves, capacity fade) instead of all sharing one set. An arriving EV starts from the latest arrival state of charge on the incoming rows of its own session, also when only an earlier incoming row holds it, or else from the one on its connection row. It never takes an estimate across a change of electric_vehicle_session_id, and the KPI and departure-audit arrival references use the same value.

  • SAC/MARLISA: features or rewards constant during warm-up are centred but no longer scaled by ~1e5; exploration, replay sampling and policy noise use seeded generators; MARLISA stores each transition with its own coordination variables and refits its demand model as data accumulates.

  • KPIs: net-exchange and cost ratios with a negative (net-exporting or market-credited) reference use 1 + (control - reference) / |reference|, so lower stays better; the counterfactual baseline exchanges no energy with the grid during power outages; multi-community ratios to a reference are ratios of summed totals.

  • Subhourly control with hourly data: the partial-load baseline top-up is converted to the control step.

  • Robustness: a PV asset unavailable event with the control or both part stops generation, not only its telemetry.

  • Terminal observation: calendar, weather and prices come from the terminal row, and endogenous values from the last executed step, as for every other observation. Episode length and termination are unchanged.

Changes that preserve trajectories and KPI values: the zero-size placeholders for absent devices, and EV chargers, are seeded, so the placeholders’ unused parameters are reproducible and building an env no longer advances Python’s global random stream; the native BAU cache keeps only the latest reference and releases it before building the next, so repeated mid-episode evaluate_v2() calls hold at most one reference env; and the reference loads only the episode, not the whole data window, when the only device marked for autosizing is PV that solar_generation disables.

Upgrade from 3.1.1 to 3.2.0

CityLearn supports Gymnasium from 0.28.1 up to, but excluding, 2.0. Dataset names now resolve against the v3.2.0 tag. Existing dataset files and export formats remain compatible.

Install citylearn[end_use_load_profiles] when generating datasets with the EULP/EnergyPlus tools. Standard simulations use the core installation.

  • Per-building reward functions: MultiBuildingRewardFunction.calculate() (used when the schema’s reward_function.type maps buildings to functions) now returns one float per building, e.g. [-1.0, -2.0] instead of the nested [[-1.0], [-2.0]], like every other reward function. With central_agent=True it returns their sum as [total]. Replace indexing such as reward[i][0] with reward[i].

  • KPI exports: the manifest records energy_provenance. With energy_provenance=False its provenance_summary and source_destinations are null instead of failing the export, and the native BAU reference uses the same setting.

Fixes that change results where they apply:

  • Observations: LSTM dynamics buildings report the simulated indoor temperature (#165); zero-based minute and second features use a 60-step cycle; occupant set-point deltas and EV/deferrable consumption bounds are corrected.

  • Dynamics: LSTM dropout is disabled at inference, so Quebec-model trajectories are deterministic for a seed and differ from earlier, noisy runs.

  • Subhourly control with hourly data (time_step_ratio other than 1): LSTM heating and cooling actions request the stated fraction of nominal power, converted to energy once; thermal-storage charging and discharge limits use the same conversion, and autosizing uses each building’s dataset/control ratio.

  • Episodes: thermal-storage discharge at the first step is counted once, and action feedback, constraint penalties and dynamic series reset with each episode, which changes second and later episodes.

Changes that preserve trajectories and KPI values: the energy_provenance option (default on), LSTM input trimming and scalar fast paths; gymnasium 1.x support; and crash fixes for hvac_mode 0, partial-day outage signals and the CLI without stable-baselines3.

Upgrade from 3.1.0 to 3.1.1

No dataset, schema or export-file migration is required. Dataset names resolve against the v3.1.1 tag by default; its dataset files are unchanged from 3.1.0.

  • Explicit random_episode_split constructor values now take precedence over the schema. Pass None to retain the schema’s setting.

  • Standby loss is an hourly fraction compounded over elapsed physical time. Subhourly SOC trajectories and their derived KPIs can therefore differ slightly.

  • Autosizing converts energy demand to power before sizing power-rated devices and batteries. Recheck automatically chosen equipment in subhourly experiments; explicitly configured equipment and thermal capacity in step kWh are retained.

  • Public energy-command interfaces and native BAU control logic are unchanged. Compare experiments using matching versions and resolved equipment settings; corrected results must not be labelled identical to old subhourly references.

Upgrade from 3.0.2 to 3.1.0

The distribution, import namespace and default dataset registry remain citylearn, citylearn and citylearn-project/CityLearn at v3.1.0. All 32 public datasets are retained byte-for-byte; no CPS production datasets are imported, and the datasets retired in 3.0.2 remain retired.

  • BAU behavior: the native BusinessAsUsualAgent now requests immediate maximum charging to 100% for connected EVs. Concurrent vehicles share the available electrical capacity proportionally. It does not schedule charging against PV, prices or departure targets. The existing constructor order is retained, but non-default EV target/deadline options are rejected explicitly; use the configurable RBC policies for those experiments. Saved BAU trajectories from 3.0.2 must not silently serve as 3.1.0 references.

  • Corrected accounting: outage dispatch shares one energy budget across served loads, storage reserves conserve energy, electrical limits use applied actions, and service/KPI denominators use executed intervals and events. Some previously saved KPI values can therefore change. Use version-matched runs when comparing experiments; keep raw energy, cost and service evidence.

  • Exports: KPI-only exports still omit episode time series but include manifest and deferrable-service JSON sidecars. CSV and partitioned Parquet output remain supported. Keep sidecars with the exported KPI file.

  • Compact histories: public market and robustness history access retains its legacy values and structure, reconstructed on demand. A returned market record is a snapshot: assign an edited record back through the history mapping rather than relying on nested in-place mutation. Repeatedly materializing full public histories can allocate substantial memory; retain compact histories during simulation and reconstruct them when needed.

  • Local schemas: roots are resolved from the schema location. Existing repository-relative roots are also accepted when found under an ancestor; an existing schema-relative root takes precedence. Resolution does not depend on the process working directory, and input files are not rewritten.

The performance changes preserve trajectories and KPI values relative to the corrected functional implementation. They do not imply equality with all historical 3.0.2 results. See the 3.1.0 release notes for measured scope and limitations.
